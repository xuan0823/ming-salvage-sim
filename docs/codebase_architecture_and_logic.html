1. 系统全景与设计哲学

《明末力挽狂澜》（Ming Salvage Simulator）是一款以 1627 年末崇祯登基为历史锚点的重度政略对话式模拟器。与市面上常见的「单轮选择题式」历史游戏不同，本项目构建了一套「自然语言交互输入 → 结构化拟旨/密令 → 宏观数值物理引擎模拟 → 多 Agent 叙事与逻辑抽取 → 状态落库」的完整闭环。

圣旨不是按钮 执行是战场

皇帝下旨并非立即见效。圣旨需要落地到地方省份与主管衙门，受制于国库银两、皇威高低、地方士绅阻力、贪腐损耗与承办官员属性。

真实财政循环 两京十三省

田赋、辽饷、盐税、商税按省分科目结算，经过士绅阻力、民变动乱、贪腐折损等严密数学模型折算为解运银，按军饷、俸禄、工程优先级逐项扣减。

高性价比推演 85%+ 缓存命中

针对 DeepSeek 等支持 Prompt Prefix Cache 的大模型进行了深度优化，静态盘面 TSV 压缩置前，240+ 回合完整通局仅需数元 API 成本。

核心游戏循环 (Turn-based Monthly Lifecycle)

一回合 = 真实历史一个月。从 1627 年 10 月至 1647 年 10 月，上限 240 个回合。月初朝会读取奏报与国库 → 召见朝臣大臣/后宫妃嫔对话 → 形成圣旨草案/密令/人事铨选 → 颁诏触发月末推演 → 日讲官撰写《月末邸报》 → 四大档房书办抽取结构化数值增量 → 财政/人事/军事/势力/局势落地入库 → 起居注与私人奏对记忆沉淀。

3. 数据模型与 41 张 SQLite 表架构

游戏数据库 data/ming_sim.db 采用 SQLite3 WAL 模式，在 ming_sim/db/schema.py 中定义了 41 张核心数据表，涵盖国家、人事、财政、地区、军事、外势、事项、建筑、科技与记忆全链路。

核心统治与大政盘面 国家级
  • game_state: 当前年、月(period)、回合(turn)、阶段(turn_phase: summoning/reviewing/awaiting_decision/issued)。
  • metrics: 核心国势四指标（国库、内库、民心、皇威）。
  • factions: 朝堂六大派系（东林、阉党、齐楚浙、勋贵、边将、内廷）满意度与影响力。
  • classes: 全国阶级（士绅、宗藩、商贾、边兵、流民、佃农等）全国汇总满意度与影响力。
  • powers / power_logs: 外部与割据势力（后金、蒙古、朝鲜、流寇等）战力、态势与行动日志。
人事铨选与廷臣名册 官员/后宫
  • characters: 人物基础属性（忠诚、能力、清廉、胆略、五维学识、生卒年月、状态 active/dismissed/imprisoned/exiled/retired/dead/candidate）。
  • offices / character_offices: 官缺职掌、权力、责任、贪腐风险与 court_grant_json 专属工具授权。
  • character_traits: 后宫调教习得的专属技能与性格变更永久记录。
  • chat_messages / minister_recaps: 历史御前奏对与跨月私下纪要。
两京十三省与全军盘面 地理/军事
  • regions / region_logs: 省级人口、动乱、民心、天灾人祸、在册田、隐田、官民田、皇庄、庄田、税率与粮产。
  • armies / army_logs: 关宁军、京营、天雄军等部队编制、人数、月费、欠饷、士气、训练、装备、忠诚与归属。
  • army_held_arms / arms_stock: 军备总库与各军兵种实持火炮、火铳、三眼铳实物库存。
  • buildings / departments / technologies: 火炮厂、常平仓、边堡、六部九卿职掌与新式科技。
事项跟踪与诏书密令 政略闭环
  • issues / issue_advances: 在办事项（0-100进度条、惯性、承办人、善恶两端含义、结案/失败条件与副作用）。
  • directives / structured_directives: 玩家自然语言草案与结构化政令模板。
  • secret_orders / secret_order_logs: 绕开朝堂的锦衣卫/司礼监密令查办、催办、进展与铁证入档。
  • legacies: 帝国修正（开局负面修正与长期增益 buff）。
  • turn_reports / turn_extractions / event_memories: 月末邸报原文、档房抽取 JSON 留痕与起居注章节记忆。

1. 大臣/后宫 Agent (Minister/Consort) ming_sim/registry.py

角色设定：扮演具体朝臣（王承恩、孙承宗、魏忠贤、毕自严等）或后宫佳丽。拥有独立脾气性格、派系私心、任事处所。
输入上下文：固定装配game_world_prompt + minister_agent_prompt + 人物档案 + 在朝名册(TSV) + 军队名册 + 上月邸报全文 + 更早章节记忆 + 近月私下奏对纪要 + 名下在办密令 + 军备库存。
能力工具：专属挂载查账、查省、查军、拟旨入档、下达密令、铨选推荐、调税立项、拨发军械等 Tools。

2. 诏书润色官 Agent (Decree Writer) ming_sim/agents.py:361

角色设定：内阁中书舍人/翰林学士。
核心职责：将玩家在御前对话中核定的多道零散草案（directives）与已办结密令证据（closed_secret_orders）整合为一篇行文典雅、符合明代圣旨诏敕风格的完整皇帝诏书。

3. 月末推演日讲官 Agent (Season Simulator) ming_sim/agents.py:532

角色设定：宏观推演日讲官。走 advanced_model 高阶推理模型。
核心职责：全面审视全国盘面与圣旨，撰写具备宏大历史纵深感的明代文风《月末邸报》。按章节叙述圣旨执行偏差、地方动荡、边防战事、朝廷暗流，并在末尾输出「陛下未知者」暗线与「待办未解」事项。

4. 档房书办四大抽取 Agent (Score Extractors) ming_sim/agents.py:563

核心架构：拆分为 4 个独立专业书办，强制严格 JSON 输出（force_json_output=True），采用「第1个模块串行暖缓存，后3个模块并行命中前缀」的高效调度：
• internal: 国势四维、收支流水、派系阶级、地区指标、财政科目变动。
• military_external: 军队战力装备、新建军队、兵种持械、外部势力动向。
• issues: 事项进度增减、新立事项、结案/撤销。
• personnel_secret: 官职任免、下狱/流放/起复、密令进展判定、崇祯结局。

5. 史官与辅助 Agent (Memory / Sanitizer / Ending) ming_sim/agents.py:602-693

• json-sanitizer: 当抽取 JSON 出现语法破损或污染时，进行无损纯语法修复。
• chapter-memory: 月末将当月诏书、邸报与落库效果提炼为一段起居注叙事，打上标签存入记忆库。
• minister-recap: 浓缩大臣个人奏对与承办纪要，下回合召见时装填其大脑。
• ending-summary: 游戏终局时通读全篇起居注历史，撰写史诗级崇祯帝史评总结。

6. 剧本生成与编辑助手 (Scenario Gen / Editor) ming_sim/agents.py:703-785

• scenario-generator: 根据玩家自然语言构思，一键生成完整的 characters.json、events.json、seed_events.json。
• scenario-editor: 支持多轮对话与 Tool Calling，可视化增删改剧本人物与事件设定。

7. 月末推演与四模块抽取深度剖析

月末推演日讲官 (Season Simulator)

  • 总标题：一句五言或七言诗，切中当月最痛之事。

8. 财政、承办与惯性数学模型

为了保证模拟世界具备严谨的数值闭环与历史物理实感，系统设计了多套经过严格参数调优的数学公式。

1. 省级财政到账率模型 (Fiscal Efficiency) ming_sim/flows.py

两京十三省税银解运入国库时，并非按账面全额到账，而是受士绅阻力、地方腐败度、民变动乱三重折损：

eff = clamp(1.0 - (gentry/100)*0.55 - (corruption/100)*0.45 - max(0, unrest-20)/100*0.30, 0.05, 1.00)

• 田赋实收 = round(官民田万亩 × 田赋亩率 / 10000 / 12 × eff)
• 辽饷实收 = round(官民田万亩 × 辽饷亩率 / 10000 / 12 × eff × (0.5 + 皇威/200))
• 盐税/商税实收 = round(账面应征月额 × eff)
• 皇庄地租(入内库) = round(皇庄万亩 × 皇庄亩率 / 10000 / 12) (皇庄直辖不受士绅折扣)
2. 承办人属性修正模型 (Assignee Modifier) ming_sim/issues.py:1200

每条在办局势指定大臣承办时，承办人不直接加减绝对点数，而是对当月基准进度施加带符号百分比修正（帝国修正机制）：

修正% = clamp(
  (能力 - 50) × 1.6% +
  (忠诚 - 50) × 0.6% +
  (清廉 - 50) × 0.5% +
  (胆略 - 50) × 0.4% +
  (领域专业度 - 50) × 0.8%,
  -80%, 80%
)

若基准进度 ≥ 0：最终增量 = round(基准 × (1 + 修正% / 100))
若基准进度 < 0：最终增量 = round(基准 × (1 - 修正% / 100))
3. 事项惯性与自然漂移模型 (Inertia & Ongoing Decay) ming_sim/issues.py:1130

未被本月圣旨或推演主动触及的事项不会静止。系统会根据其 inertia（惯性值）进行自然漂移：

  • 负向危机事项 (Crisis): 如「陕北流民聚众」，若无人办理，每月由于责任无着与惯性使进度条向恶端下滑（bar_value -= inertia），直至触发 fail_condition 爆发起义。
  • 承办人缺位惩罚: 若事项无承办人，自动施加 net_pct = -35% 的延误惩罚；承办人死亡或被罢官则按无人实办处理。
  • 持续效果扣费 (ongoing_effects): 事项在进行期间每回合自动扣减国库维护专款、边防压力加成，结算后自动落账。

9. 前沿工程与 Token 缓存优化实践

模拟器要支撑长达 240 回合的长线游玩，必须彻底解决大模型长上下文的延迟与费用瓶颈。本项目在 ming_sim/agents.py 和 ming_sim/simulation.py 中实现了多项开创性的 Prompt 缓存工程优化。

真 TSV 表格压缩 -25% Token 消耗

抛弃传统的冗余 List[Dict] JSON 格式，将 regions、armies、buildings 等大型表格转为单行 Tab 分隔的真 TSV 文本块，去除了海量的字段名转义字符。

字节级前缀一致对齐 85%+ Cache Hit

Simulator 与 4 个 Extractor 的 System Prompt 开头采用同源 build_simulator_context() 构造，首字节完全一致。Simulator 率先运行创建缓存，后续 4 个 Extractor 瞬间命中共享缓存。

稳态在前，易变在后 防止前缀分叉

在组装 Prompt 时，严格按照「最稳定的世界规则 → 变化极小的建筑/科技预设 → 相对稳定的官员名册 → 易变的地区军队数值 → 当月诏书与即时指令」顺序排列，最大限度保住前缀缓存命中长度。

SSE (Server-Sent Events) 打字机与思考流管道 web_app.py:2800+

Web 界面采用多通道 SSE 实时推流。在 /turn/resolve/stream 中，后端通过后台工作线程异步运行 GameSession.resolve_turn()，利用线程安全的 queue.Queue 将阶段状态 stage、模型思考过程 thinking、正文文字流 text 以及最终结算数据 done 实时泵送到前端，带来流畅的古风奏折阅读体验。
